## 今日のひとこと

Linuxでは、デバイスもファイルとして扱い、`/dev`、パーティション、ファイルシステム、マウントという層を通して利用する。管理では「いま何が認識され、どの形式で、どこに接続され、どれだけ使われているか」をコマンドで確認することが大切。

## 1. デバイス管理

- デバイスとは、マウス、キーボード、ディスク、プリンタなど、コンピュータに接続された装置や内蔵部品の総称。
- デバイスファイルはユーザー側の窓口で、`/dev` 配下に置かれる。
- デバイスドライバは、受け取った操作を実際のデバイスに対して実行する。カーネルモジュールとして組み込まれる。
- `udev` はデバイスファイルを動的に生成・管理する仕組み。

### udevによる認識の流れ

1. デバイスを接続する。
2. Linuxカーネルが検知し、情報を `/sys` 配下に作成する。
3. `udevd` にデバイス認識が通知される。
4. `udevd` が `/sys` の情報と命名ルールを参照する。
5. `/dev` 配下にデバイスファイルを生成する。

- 標準ルール: `/usr/lib/udev/rules.d/*.rules`
- 追加ルール: `/etc/udev/rules.d/*.rules`
- PCIデバイス確認: `lspci`（`-v` で詳細、`-s` で識別番号を指定）
- USBデバイス確認: `lsusb`（`-t` でツリー、`-v` で詳細）

## 2. ディスク管理

- HDDは比較的安価で大容量・長寿命だが、重く低速。
- SSDは軽量・高速・耐衝撃性があるが、比較的高価で書き込み回数に上限がある。
- SATA/SCSI系ディスクは、認識順に `/dev/sda`、`/dev/sdb` のように命名される。
- パーティションは `/dev/sda1`、`/dev/sda2` のように末尾へ番号が付く。
- 新しいディスクは接続しただけでは使えない。基本は「認識 → パーティション作成 → ファイルシステム作成 → マウント」の順。
- スワップは物理メモリ不足時に補助的に使う領域。物理メモリより低速。
  - 作成: `mkswap`
  - 有効化: `swapon`
  - 確認: `swapon -s`
  - 無効化: `swapoff`

## 3. パーティションとLVM

| 項目 | MBR | GPT |
| --- | --- | --- |
| 主な対応ファームウェア | BIOS | UEFI |
| 容量上限 | 2 TB | 9.4 ZB |
| 基本的な上限 | 基本パーティション4個 | 128個 |
| 予備領域 | なし | あり |

- MBRで5個以上必要な場合は、基本パーティションの1つを拡張パーティションにし、その中へ論理パーティションを作る。
- `fdisk`: MBRを操作。
- `gdisk`: GPTを操作。
- `parted`: MBR/GPTの両方に対応。変更が即時反映される点に注意。
- 対話操作の基本: `p` 確認、`n` 作成、`d` 削除、`w` 保存終了、`q` 破棄終了。
- LVMは、複数の領域をまとめて柔軟に論理ボリュームを作る仕組み。
  - `PV`（物理ボリューム）→ `VG`（ボリュームグループ）→ `LV`（論理ボリューム）
  - LVは容量の拡張・縮小やスナップショットを利用できる。
  - デバイスファイルは主に `/dev/mapper` 配下にある。

## 4. ファイルシステム

- ファイルシステムは、ディスク上のデータをファイルやディレクトリとして管理する仕組み。
- 作成には `mkfs` 系コマンドを使う。例: `mkfs -t ext4 /dev/sdb1`。
- 主なLinux向け形式には ext系やXFSがあり、用途・機能・制限が異なる。
- `mke2fs` はext系ファイルシステムを作成する。
- `tune2fs` はext系の設定確認・変更に使う。
- `fsck` はファイルシステムの検査・修復に使う。原則としてアンマウントした状態で実行する。
- `xfs_repair` はXFSの検査・修復に使う。
- ラベルやUUIDを使うと、デバイス名の変化に左右されにくい指定ができる。

## 5. マウントと容量管理

- マウントとは、ファイルシステムをルートディレクトリ以下のディレクトリへ接続すること。
- 接続先のディレクトリをマウントポイントという。通常は空のディレクトリを使う。
- `mount`: マウントの実行・現在の状態確認。
- `umount`: アンマウント。
- `lsblk`: ブロックデバイス、容量、種類、マウントポイントをツリー表示。
- `blkid`: UUID、ファイルシステム形式、ラベルを確認。
- 永続設定は `/etc/fstab` に記述する。

```text
デバイス  マウントポイント  ファイルシステム  オプション  dump  fsck
```

- `mount -a` は `/etc/fstab` に従って対象をまとめてマウントする。
- アンマウントできないときは、使用中のプロセスを `lsof` や `fuser` で確認する。
- `df -h`: ファイルシステム単位の容量を読みやすい単位で表示。
- `df -i`: iノードの使用状況を表示。
- `du -sh`: ファイル／ディレクトリ単位の使用量を表示。
- データ領域に空きがあっても、iノードを使い切ると新しいファイルは作れない。

## 6. 印刷管理

- CUPSはLinuxで広く使われる印刷システム。
- 印刷要求を印刷ジョブ、ジョブを一時的に蓄える場所を印刷キューという。
- CUPS設定: `/etc/cups/cupsd.conf`
- プリンタ設定: `/etc/cups/printers.conf`
- `lp` / `lpr`: 印刷要求を送る。
- `lpq` / `lpc`: 印刷キューやジョブを確認・操作する。
- `lprm`: 不要な印刷ジョブを削除する。
- `lpstat`: プリンタ、ジョブ、システム設定の状態を確認する。
- `lpadmin`: プリンタの登録、削除、設定変更を行う。

## 寝る前の3分復習

1. デバイスファイルはどこにある？ → `/dev`
2. 接続情報をカーネルが保存する場所は？ → `/sys`
3. PCIとUSBの確認コマンドは？ → `lspci` / `lsusb`
4. ディスクを利用可能にする流れは？ → 認識 → パーティション → ファイルシステム → マウント
5. MBR/GPTに対応する操作コマンドは？ → `fdisk` / `gdisk`（両対応は `parted`）
6. LVMの3層は？ → `PV` → `VG` → `LV`
7. 永続マウントの設定ファイルは？ → `/etc/fstab`
8. 全体容量・iノード・個別容量の確認は？ → `df -h` / `df -i` / `du -sh`
9. Linuxの印刷システムは？ → CUPS
